# JEQ

macOS 系统级音效处理器，采用**场景模式 + 独立低音模块 + 高级标准 10 段 EQ** 的分层结构。
菜单栏常驻，不装虚拟声卡驱动、不装内核扩展，
退出即完全归还音频。基于 macOS 14.4+ 的 Core Audio **process tap** API。

---

## 1. 为什么是这个架构

macOS 长期没有系统级 EQ。历史上只有三条路：

| 路线 | 代表 | 代价 |
|---|---|---|
| 内核扩展驱动 | Soundflower（已死） | 内核态，签名困难，系统更新即崩 |
| HAL 插件（用户态驱动） | BackgroundMusic / BlackHole / eqMac | 要装驱动、要重启 `coreaudiod`、蓝牙/HDMI 上常出问题 |
| **Process tap（本方案）** | 本文 | **零安装**，进程退出音频自动回流 |

Process tap 从 macOS 14.4 起可用：系统把「所有进程送往输出的混音」以虚拟流形式暴露给应用，
应用处理后再写回物理设备。没有驱动、没有 TCC 之外的特权。

### 信号链

```
所有 App ──▶ CoreAudio 混音 ──▶ [tap] ──▶ 聚合设备(输入流)
                                              │
                                    IOProc（同一时钟域）
                                              │
                    preamp ─▶ 31×1/3oct 滤波器组 ─▶ trim ─▶ 软限幅
                                              │
                                    聚合设备(输出流) ──▶ 物理设备(DAC)
```

关键设计选择：**把物理设备作为聚合设备的主子设备（main sub-device），tap 放进 tap list
并开启 drift compensation**。这样输入流与输出流共用同一个硬件时钟，不需要环形缓冲、
不需要漂移补偿逻辑，实测端到端延迟就是一个 buffer（512 帧 ≈ 10.7 ms）。

单 IOProc 一次拿到输入与输出缓冲，直接原地处理 —— 没有 memcpy 中转，没有线程切换。

## 2. 三个必须知道的坑（本机实测，非猜测）

### 坑 1：聚合设备的输入流不止 tap 一条

聚合设备若把物理设备加为子设备，其输入流 = `[设备自身输入流…, tap 流]`。本机实测
`inBL.count == 2`，`buf[0]` 是 USB 声卡自己的麦克风输入（静音），`buf[1]` 才是 tap。
**tap 流固定在末尾**，按 `inBL.count - 1` 取。

曾尝试用 `kAudioSubDeviceInputChannelsKey: 0` 让子设备只贡献输出通道，实测被忽略，
输入流数量不变。因此索引规则必须靠代码保证，并对通道数做校验。

### 坑 2：不排除自己 → 正反馈自激

全局 tap 若用空排除列表，会把自己写回设备的输出**再次捕获**。直通（增益 1）时它表现为
"轻微过冲"，看起来没事；一旦增益 > 1 就发散：

```
输入峰值 11.5 → 限幅 0.95 → ×增益 3.6 → 写回 → 又被 tap 抓到 → …
```

实测偏差从预期的 +7.37 dB 变成 +11.58 dB，峰值越积越高。

正确解法是 `CATapDescription(stereoGlobalTapButExcludeProcesses:)` 传**自己的 CoreAudio
进程对象 ID**（从 `kAudioHardwarePropertyProcessObjectList` 里按
`kAudioProcessPropertyPID == getpid()` 查）。**直接传 PID 会得到 `!obj`
（kAudioHardwareBadObjectError）** —— 这是最容易踩的一步。

### 坑 3：tap 是音量前，不要做"音量补偿"

早期误判 tap 抓的是音量后信号，于是写了 `makeup = 1/deviceVolume` 的反算补偿。
排除自激之后测得：输入幅度 0.2508，源信号幅度 0.25 —— **tap 是单元平的音量前混音**。
那个 0.52 的"衰减系数"其实是自激污染造成的假象。

所以写回设备时音量只会被硬件施加一次，**任何反算补偿都会直接把输出推过 0 dBFS**
（实测输出峰值 1.22）。该逻辑已移除。

另外：限幅器必须是**最后一级**。放在 makeup 之前，增益会突破保护阈值。

## 3. DSP

现在的模型分为三层，和成熟 EQ 产品的使用方式一致：

1. **场景模式**：音乐 / 电影 / 游戏 / 人声 / 重低音。使用业界常见的标准 10 段中心频率
   `31.5 / 63 / 125 / 250 / 500 / 1k / 2k / 4k / 8k / 16k Hz`。标准模式中频点位置固定，
   拖动只调整该频段的效果增益，不会把整条频响当成总音量滑杆。
2. **独立低音模块**：关闭 / 自然低音 / 纯低音+ / 超低音；可选择 40 / 60 / 80 / 100 / 125 Hz
   中心和轻 / 中 / 强三档。三种性格使用不同的低频宽窄和中低频衰减，而不是把低频全部一起拉高。
3. **清晰度模块**：独立处理 2–6 kHz 人声和细节；与低音模块、基础 EQ 分开保存。

高级模式仍保留原来的自由曲线：最多 10 个控制点，曲线由相邻控制点在对数频率上插值
（余弦缓动）。自由模式可拖频率；一键「对齐到标准 10 段」可把当前形状重采样到固定频点。
6 个旧版经典预设与 5 个新场景并列显示在主面板顶部，DIY 卡片也在同一层级；
已有自定义卡不会被覆盖。

声音不是直接用这几个点做参数 EQ，而是由一组**固定 1/3 倍频程峰值滤波器**（20 Hz–20 kHz，
31 个，Q 1.5）去逼近这条曲线：每个滤波器的增益取自曲线在它中心频率上的值，再解一个线性
方程组修正相邻滤波器重叠的影响，使叠加后的总响应在中心频率上贴合目标曲线。
单个滤波器增益在预设曲线下都在 ±10 dB 内，dB 域近似线性，所以这个拟合是稳定、可重复的。

- **固定防爆音余量**：按整条最终曲线的最大正增益一次性预衰减（另留 0.35 dB 峰值余量）。
  它只随模式/曲线改变，**播放过程中不随歌曲、电平或峰值变化**，因此不会出现一首歌
  音量忽高忽低。正增益被线性抵消后，低音相对其他频段的提升仍然保留。
- **末级软限幅**：只在极端瞬态超过约 −0.22 dBFS 时介入，渐近上限约 −0.01 dBFS，
  `tanh` 平滑，无硬削波。正常曲线下固定余量已经足够，限幅器基本不介入。
- 另有手动 Trim，可只改输出响度，不进频响曲线。
- 系数用 RBJ Audio EQ Cookbook，Direct Form II Transposed，Float 单精度。
- 参数发布：UI 线程 `os_unfair_lock` 写入，音频线程 `trylock` + 独立快照缓冲区，
  抢不到锁就沿用上一帧快照 —— **音频线程永不阻塞、永不读到半个参数集**。

### 直接操作曲线（纯图形）

每个控制点在曲线上是一个节点，节点旁直接标着频率（如 `38 Hz`、`1.2 kHz`）。
曲线按定义经过每个节点，下方没有频段条和参数滑杆。

| 操作 | 效果 |
|---|---|
| 双击空白 | 自由曲线中在该位置（对应频率/增益）新增控制点（最多 10 点） |
| 拖动节点 | 横向改频率、纵向改该点增益；只影响相邻两点之间的曲线，其他节点不动 |
| 拖动曲线本体 | 整条曲线一起动：纵向 = 所有节点增益同量平移；⌥ + 拖动 = 所有节点频率等比缩放（保持形状） |
| 右键节点 | 删除 / 增益归零 / 启用禁用 |
| ↑ ↓ ← → | 选中点增益 ±0.1 dB、频率 ×/÷1.02；⇧ 加速 |
| Delete | 删除选中点（仅自由曲线） |

抓曲线时整条线会亮起柔光、光标变成手形，并显示原曲线的虚线作为参照；
右上角实时给出「整体移动 +x.x dB」或「整体移频 ×x.xx」。所有节点共用同一偏移量，
曲线形状不变；碰到 ±18 dB 或 20 Hz–20 kHz 边界时整体停住，不会被压扁。
标准 10 段模式锁定中心频率，只允许上下调对应频段的增益。

### 电平表

图上方是输入/输出立体声电平表：

- **亮条 = 峰值**（−54…0 dBFS 刻度，绿→黄→红）；**白线 = RMS**；**细线 = 峰值保持**（1.3 s 后回落）。
- IN / OUT 每行上条是左声道、下条是右声道；单声道设备会把同一路复制到两条，避免看起来缺一声道。
- 峰值瞬态上升、24 dB/s 回落；RMS 快起慢落，读数不会一闪一闪。
- IN 右侧圆点：输入达到 0 dBFS（源信号已经削波）。OUT 右侧圆点：输出接近 0 dBFS，
  看到它常亮应检查固定防爆音余量或降低响度微调。
- 表头直接读音频线程按声道累计的峰值与均方值；累计值由 UI 取走后清零，
  所以两次刷新之间的瞬态峰值不会漏掉。面板关掉再打开时会先丢弃旧读数，不会把
  几分钟前的瞬态当成当前电平。

### 场景、经典预设与 DIY

场景是**只读模板**。修改 10 段增益、低音模式/中心/强度或清晰度时，整套音色参数会自动写入
一张**常驻「DIY」卡**并永久保存；点别的场景/经典预设不会让它消失，点 DIY 可原样载回。
右键 DIY 可回到基础预设、用当前音效覆盖或删除。
自定义卡按输出设备分别保存。旧版本的 8 段/4 段曲线会按原样迁移，不会因为升级被改写。

固定防爆音余量、Trim、限幅和开机启动属于全局处理选项，不写进卡片。

### 低音模块

- **自然低音**：低频轮廓较宽，兼顾鼓点厚度与人声自然度。
- **纯低音+**：低频更集中在所选中心，并轻度压低更高一点的中低频拖尾，听感更干净。
- **超低音**：重心压到 20–80 Hz，适合电影和下潜型低频；不会采用社区常见的
  `60 Hz +10 / 80 Hz +8 / 100 Hz +6` 激进叠加配置。

经典预设保留在主面板顶部，包括直通、低音增强、深潜、打击感、暖厚和影院，
用于兼容旧使用习惯和已有自定义卡。

## 4. 构建与安装

```bash
git clone https://github.com/jukie-xu/JEQ.git
cd JEQ
bash ./install.command
```

只构建、不安装：

```bash
./build.sh                       # 产出 build/JEQ.app（无需 Xcode 工程）
```

一键构建 + 清理 + 安装：双击 `install.command`（或终端执行 `./install.command`）。它会：

1. 先编译新版本（编译失败不会动旧 app）；
2. 退出正在运行的 JEQ / SubEQ；
3. 安装一份到 `/Applications/JEQ.app`（无写权限时落到 `~/Applications/JEQ.app`）；
4. 删除 `/Applications` 与 `~/Applications` 下其余 `JEQ.app` / `SubEQ.app` 副本
   （无权限时弹一次管理员授权），并清理旧版 `com.subeq.app` 的 LaunchAgent；
5. 启动，并核对全系统只剩这一份。

> 如果双击没反应（工作目录是挂载进来的，`.command` 在 macOS 侧可能没有可执行位），
> 打开终端执行：`cd "<项目目录>" && bash ./install.command`。详细步骤见 `安装方法.txt`。

`build.sh` 每次先清空 `build/`，所以编译输出也只有 `build/JEQ.app` 一个产物。

### 从 SubEQ 更名

- Bundle ID 由 `com.subeq.app` 改为 `com.jeq.app`，应用名与可执行文件都是 `JEQ`。
- 首次启动会自动把旧域 `com.subeq.app` 里缺失的配置（预设、自定义卡、全局参数）搬进
  `com.jeq.app`；旧域不删除，回退时数据还在。
- 系统权限跟着新 App 走：首次启用会重新请求一次「系统音频录制」。

### 图标与开机启动

- 应用图标：`Resources/JEQ.icns`（1024 源图 `Resources/JEQ-1024.png`），五根橙色声波柱 + 同心涟漪，
  菜单栏用同一组声波柱做 18pt 模板图 `MenuBarIcon.png`，随菜单栏明暗自动反色。
- 开机启动：面板「更多」→「开机启动」。优先注册系统登录项（`SMAppService`）；
  ad-hoc 签名下若系统拒绝，会自动退回 `~/Library/LaunchAgents/com.jeq.app.plist`，
  开关状态以实际生效方式为准。关闭时同时注销登录项并删除 LaunchAgent。

要求：macOS 14.4+，Xcode Command Line Tools（Swift 6.x）。产物 ad-hoc 签名，未公证。

> 本机 Xcode 27.1 的 SwiftUI 宏插件（`swift-plugin-server`）返回 "malformed response"，
> 导致 `@State` 无法展开。项目已避开该宏（界面展开状态放在 `AppState`），
> 其余 `@ObservedObject / @StateObject / @Binding` 均可正常编译。

首次点「启用」时系统会请求**系统音频录制**权限。授权后菜单栏出现紫色指示器，正常现象
（进程 tap 的机制如此，不录像、不落盘）。

## 5. 如何验证（不靠"听起来像"）

```bash
JEQ.app/Contents/MacOS/JEQ --selftest    # 离线：理论频响 vs 实测增益
JEQ.app/Contents/MacOS/JEQ --curvetest   # 整条曲线拖动：平移 / 移频 / 边界夹取
JEQ.app/Contents/MacOS/JEQ --modetest    # 标准 10 段 / 场景 / 低音模块 / 固定余量防削波
JEQ.app/Contents/MacOS/JEQ --metertest   # 电平表弹道：回落 / 峰值保持 / 削波灯
JEQ.app/Contents/MacOS/JEQ --liveproof deepSub   # 实时：tap→DSP→设备 端到端
JEQ.app/Contents/MacOS/JEQ --snapshot [--advanced] [--out <目录>]  # 离屏渲染面板
```

`--curvetest`、`--modetest` 与 `--metertest` 都是断言测试，不需要音频设备，失败时退出码非 0。
`--snapshot` 用 `ImageRenderer` 把菜单栏面板渲染成 PNG（默认写到系统临时目录，
可用 `--out` 指定目录）。没有辅助功能权限、无法脚本点击菜单栏图标时，这是检查排版的
唯一可靠手段（离屏渲染下 `Toggle` 与 `.link` 按钮会显示成系统占位图，真机正常）。
`ImageRenderer` 不渲染 NSView，所以截图模式下曲线区会换用同参数的 SwiftUI 静态预览
（`CurvePreview`），电平表则喂一组固定读数；排版与真机一致、只是不能交互。

`--selftest` 对每个预设、每个频点，同时给出**目标曲线值**与**跑真实信号测出的值**。
节点频率处滤波器组与曲线贴合得最紧；两个中心频率之间是滤波器组的插值，偏差会稍大一些，
具体数值以实际输出为准：

```
— 低音增强：20Hz +8.0dB / 40Hz +12.0dB / 70Hz +12.0dB / 110Hz +9.0dB / ...
   freq      目标dB    实测dB    偏差
     25 Hz     ...       ...      ...
```

`--liveproof` 走完整链路（自己 spawn `afplay` 播放 60 Hz + 1 kHz 复合测试音，
避免与采集的时序错位），比较输出/输入在同一频点的比值与目标曲线的差值。
直通时输出与输入应逐位同幅；低频段不应有高通滚降 —— 这是重低音能成立的前提。

## 6. 已实现 / 未实现

**已实现**

- 场景模式：音乐 / 电影 / 游戏 / 人声 / 重低音，固定标准 10 段中心频率
- ViPER 风格独立低音模块：自然 / 纯低音+ / 超低音，5 个中心频率 + 3 档强度
- 独立 2–6 kHz 清晰度模块；固定线性防爆音余量，不随歌曲电平变化
- 自由曲线最多 10 个控制点，可一键对齐标准 10 段；31 个固定 1/3 倍频程滤波器逼近目标曲线
- 曲线直接编辑（纯图形）：节点压在曲线上，拖动只影响相邻段；抓曲线本体可整体平移增益、⌥ 拖动整体移频；双击加节点、右键菜单、方向键微调；频率标签贴在节点上随波形移动
- 5 个场景 + 6 个兼容旧版的经典预设 + 一张保存完整音色模块的常驻「DIY」卡
- 输入 / 输出立体声电平表：峰值 + RMS + 峰值保持、dBFS 刻度、输入削波与限幅介入指示；参数改动即时生效（10 ms 内）
- 按输出设备记忆配置（含自定义卡）；输出设备切换自动重建引擎
- 引擎重启、错误回显、旁通
- 应用图标 + 菜单栏模板图标；开机启动开关（系统登录项优先，LaunchAgent 后备）

**未实现（按需再加）**

- 逐 App 音量 / 逐 App EQ（需要按进程分别建 tap）
- 每段独立的 Q / 滤波器类型（当前由曲线 + 固定滤波器组决定）
- 可命名的多套自定义配置（目前每台设备一张自定义卡）
- 音乐制作场景：DAW 直连声卡时绕过系统混音，EQ 不生效（架构限制，非 bug）
